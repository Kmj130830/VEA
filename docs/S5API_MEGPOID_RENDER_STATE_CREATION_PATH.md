# AI Megpoid V7 render-state creation path

Date: 2026-11-21

## Evidence scope

This note records a static Ghidra trace of the supplied S5API.dll. The DLL was not executed. Function names are analyst-assigned Ghidra labels, and the evidence establishes call/dataflow relationships rather than runtime success for every voicebank or project.

## High-level initialization path

In the recovered high-level initializer `Func_47a12a73`, one branch performs the following operations:

1. Calls `FUN_180126940()` and stores the returned wrapper at owner offset `+0x20E8).
2. Resolves a model-object property using a generated lookup key and reads its value into a local string-like object.
3. Passes the created render-state wrapper and the resolved value to `FUN_180127220(root, value)`.
4. Calls `FUN_180127630(root, 0)` on the same wrapper.

The recovered pseudocode places these calls in the same branch. The semantic name of the hashed property and the branch predicate are not assigned here.

## Root allocation and initialization

`FUN_180126940` allocates an 8-byte wrapper and a `0x37A0`-byte root object, zeroes the root, and calls `FUN_1800bca40(root)` to initialize its embedded state. This is an empty root creation path, not a deep copy of a populated model.

The separate public copy path `FUN_1801269F0` calls `FUN_1800ccce0`. The latter allocates and initializes another root, resolves the source root through `FUN_1800c4730`, and copies its contents through `FUN_1800cdbb0`. It should therefore be treated as a clone/copy path, not as the initial model-population path.

## Model-value selection, JSON serialization and residual-block construction

The high-level lookup key is generated by `FUN_18001acc0`, which formats four 32-bit words from the initializer's constant buffer as eight-digit lowercase hexadecimal words. The resulting key is `154c806ba4d274fad9c7484acdc1779e`.

`FUN_180081940` performs a direct child-property lookup in the selected model object. The supplied VTB2 object-tree audit finds the key at:

```text
$/5be3f5d6495f68286523e230e2d0d9a4/154c806ba4d274fad9c7484acdc1779e
```

All eight `FUN_1800ced10` factory families are matched below the descendant `43726e4ce752ea6cc300dc2fca3e8372`, confirming that this is the selected branch containing the runtime-block source properties.

The value returned by the lookup is serialized by `FUN_18000ee30`. Its decompilation establishes recursive JSON serialization:

- node type 3 writes a string value;
- node type 4 emits an array and recursively serializes each element;
- node type 5 emits an object, serializing each key and value recursively;
- other primitive node types are converted by `FUN_180083780` and written to the output string.

The public wrapper `FUN_180127220(root, jsonText)` then calls `FUN_1800af170`. That routine invokes `FUN_1800b8f60`, which rejects empty input, parses the JSON text through `FUN_1800b9200`, and transfers the parsed value into an owned typed object through `FUN_1800e06f0`. The observed parser flags are `1, 0, 0`. The resulting tree is passed to `FUN_1800ced10`, which builds the residual-block records and associated workspaces.

The complete native sequence is therefore:

```text
model object
  -> FUN_180081940(key 154c806b...)
  -> FUN_18000ee30(JSON serialization)
  -> FUN_180127220
  -> FUN_1800af170
  -> FUN_1800b8f60(JSON parse into owned typed tree)
  -> FUN_1800ced10(residual-block record population)
  -> FUN_1800dc4b0(recursive temporary-tree cleanup)
```

`FUN_1800dc4b0` is the recursive typed-value cleanup routine. It walks allocated object/array contents and frees dynamic string/container storage according to each node type tag. It is cleanup after population, not a second model conversion.

### Android mapping

The Android parser already stores the decoded VTB2 JSON as an immutable `S5ModelObjectTree`. Repeating S5API's stringify-then-parse round-trip is unnecessary for indexing because the same selected object subtree is already available. The app now exposes this exact branch through `S5ModelObjectTree.subtreeAtPath()` and `S5VoicebankModelPackage.residualRuntimeConfigTree`, using:

- `5be3f5d6495f68286523e230e2d0d9a4`
- `154c806ba4d274fad9c7484acdc1779e`

The eight runtime-block key factories are now indexed only inside this selected subtree, matching the native model branch rather than searching unrelated sibling model data. Unit tests cover exact-path extraction and ensure a duplicate key in a sibling branch cannot leak into the selected index. The Android subtree is a structural equivalent of the selected JSON value; byte-for-byte parity against the vendor's serialize/parse round-trip has not been claimed.


## Follow-up configuration

`FUN_180127630(root, value)` is a thin wrapper which forwards the root and 32-bit value to `FUN_1800af230`. In the high-level initialization branch above, the supplied value is zero.

The decompilation of `FUN_1800af230` shows that it writes a boolean at root-relative offset `+0x618`, setting it to `(value != 0)`. When root field `+0x78` is non-null, it creates a replacement object through `FUN_180129240`, passing values read from root offsets `+0x0C`, `+0x04` (twice), `+0x10`, `+0x618`, `+0x61C`, `+0x620`, and `+0x3418`; it then releases the previous object via `FUN_180129A50` and frees its allocation. The semantic names of these fields and the object returned by `FUN_180129240` are not established yet.

Thus the observed `FUN_180127630(root, 0)` call sets the root flag at `+0x618` to false and conditionally refreshes the object at `+0x78`. It is not safe to describe the routine as a generic finalizer without further field/consumer tracing.

## Relationship to the forward path

The separately recovered forward path is:

```text
Func_92864e29
  -> FUN_180126c20
  -> FUN_1800aec40
  -> FUN_1800c7ad0
```

`FUN_1800c7ad0` consumes the runtime descriptors and residual block/state vectors owned by the render-state root. The root-relative layout is documented in `S5API_RENDER_STATE_DESCRIPTOR_LAYOUT.md`; do not infer a field's meaning from a matching numeric offset in a different object's base.

## Android porting implications

The Android implementation already parses and hash-validates the five Megpoid/shared model members, indexes the eight VTB2 residual-block property families, prepares the eight residual blocks, and packs the nine VTMG named-layer parameter sets. These are input/parameter preparation stages.

The newly mapped native path provides the missing high-level connection between a model-object value and `FUN_1800ced10`. Android still needs a behaviorally equivalent implementation of the configuration conversion at `FUN_1800b8f60`, the complete population of all root descriptors consumed by `FUN_1800c7ad0`, and validation of `FUN_1800af230`. The full forward graph, phoneme/event preparation, output-domain conversion, and verified PCM rendering remain incomplete.

No successful Megpoid vocal render or WAV output is claimed by this analysis.


## Confirmed pre-residual tensor keys

The initialization routine resolves three properties before building
per-sequence descriptors. The embedded constants passed to
\`FUN_18001acc0\` produce the exact keys:

- Dense weights: \`dd8f659ac91cbd5ef58ebd6ed786339e\`.
- Normalization scale: \`6121c88871cfb21dab889701aef1922a\`.
- Normalization bias: \`f860a37573c14d61e3a339d70eadd90f\`.

The dense descriptor's bias flag is zero. The normalization constructor
stores scale first at descriptor \`+0x08\`, then bias at \`+0x18\`; its
epsilon is float32 \`1.0e-6\`. Android now indexes these exact VTB2 keys and
can construct the Dense + Global-Normalization stage when supplied with the
active render-state feature dimensions. Temporal and banked-linear per-index
property keys remain unresolved.


## Sequence-indexed model tensor tables

The six factory initializers provide sixteen keys each. Temporal weights are
returned by \`FUN_1800e8620\` and temporal optional bias by
\`FUN_1800e76c0\`. Standard banked-linear weights are returned by
\`FUN_1801256a0\` and optional bias by \`FUN_180122880\`. The alternate path
uses \`FUN_180124740\` for weights and \`FUN_1801237e0\` for bias. Android
indexes these keys recursively in the selected VTB2 render subtree.

The standard banked source tensor is stored as
\`[inputFeature][outputFeature][bank]\`. The native descriptor constructor
transposes it into per-bank row-major matrices; Android reproduces that
permutation before calling the native projection kernel. Active sequence
count, feature dimensions, kernel/bank counts and bias flags remain
runtime descriptor metadata and are not inferred from the key tables.


## Five sequence slots and reverse feedback sweep

The dispatcher uses five sequence-feature slots and four transitions.
Temporal factories 0..3 run in ascending order to produce the four following
slots. The reverse pass uses banked factory 0 on slot 4 and writes slot 3;
its residual row 3 output becomes the input to banked factory 1, which writes
slot 2. The same pattern continues through rows 2, 1, and 0.

The Android \`S5MegpoidSequenceTransitionPipeline\` mirrors this feedback
order: Dense + normalization runs once, Temporal runs forward, and each
Banked projection is immediately followed by its matching residual row.
Bank count is folded into the contiguous position axis because the native
banked result is \`[feature][position][bank]\`. This pipeline still starts
from prepared features; it does not synthesize features from note/phoneme
input.


## Corrected native sequence-slot count

The supplied AI Megpoid V7 runtime-options tree decodes to \`param[5] = 4\`
and \`param[6] = 2\`. The initializer creates four feature slots and runs
the Temporal and standard Banked descriptor loops three times each. It
creates eight residual records from the 4×2 grid.

The render order is Temporal[0], Temporal[1], Temporal[2], Residual row 3,
then Banked[0]/Residual row 2, Banked[1]/Residual row 1, and
Banked[2]/Residual row 0. This corrects the earlier five-slot/four-transition
assumption and is the sequence used by the Android pipeline.

## Focused render-root scalar provenance trace

A separate, focused Ghidra 12.2 report for FUN_1800ced10, FUN_1800bca40
and FUN_1800d5a00 confirms the output-descriptor scalar sources:

- Runtime-options param[1] is stored at render root +0x04.
- Runtime-options param[3] is stored at render root +0x0C.
- Runtime-options param[4] is stored at render root +0x10 and cast to float
  by FUN_1800d5a00 before it is passed to the output descriptor.
- The model-population function does not assign the output-specific fields
  at +0x61C, +0x620, +0x1F74, +0x3418 or +0x1F75. Those retain blank-root
  constructor defaults from FUN_1800bca40: 0, false, false, 0 and false.

For AI Megpoid V7, this resolves the output-transform inputs to
outputSamples=320, geometry=fftSize=1024 and floatParameter=32000.0, with
a full symmetric Hann frame window and both output-window mode flags off.
The Android runtime-options descriptor now creates the output-transform
input carrier from these model fields and verified constructor defaults.
