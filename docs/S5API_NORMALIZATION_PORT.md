# S5API normalization and GELU operator port

Date: 2026-11-19

## Recovered call sequence

The layer path in `FUN_1800c5d50` performs these stages in order:

1. `FUN_1800c67e0` runs the convolution/conditioning path. For 7x7 kernels it selects the scalar/SIMD depthwise-convolution dispatcher.
2. `FUN_180130b70` selects the layer-statistics kernel. The scalar target at `0x180130ce0` returns `sum(x)` and `sum(x*x)`.
3. The caller calculates:
   - `N = axis0 * width`
   - `mean = sum / N`
   - `variance = max(sumSquares / N - mean * mean, 0)`
   - `std = sqrt(variance + model_epsilon)`
4. The normalization output then enters `FUN_18012cb50`, which selects a GELU implementation.
5. After the GELU stage, the path applies the residual affine merge through `FUN_1800d8720` (scalar) or `FUN_1800d84e0` (vector).

This is a recovered portion of a model layer. It does not establish the complete model graph or every memory-layout/stride requirement around the enclosing block.

## Mean and inverse-standard-deviation helper

The scalar post-statistics expression from `FUN_1800c5d50` is now ported separately as `vea_s5_compute_mean_invstd_f32`:

```text
mean = sum / N
variance = sumSquares / N - mean * mean
variance = max(variance, 0)
inverseStd = 1 / sqrt(variance + epsilon)
```

The function preserves this float32 operation order and rejects zero count, negative/non-finite epsilon, non-finite input statistics, and null outputs. It is exposed as `NativeS5TensorBridge.computeMeanAndInverseStd`. Tests cover ordinary variance, a negative pre-clamp variance, constant input with epsilon, and invalid arguments.

This helper returns only mean and reciprocal standard deviation. The enclosing per-channel gamma/beta indexing and complete block memory layout are not yet wrapped into a single normalization kernel.

## GELU selector and formula

`FUN_18012cb50` caches and selects the implementation:

- AVX-capable path: `FUN_18012cff0`
- SSE/vector path: `FUN_18012cbc0`
- scalar path selected at CPU tier 3: `FUN_18012ca50`

The scalar implementation's decompiled body establishes the operation exactly:

```text
x = scale * input[i] + bias
input[i] = x / (1 + exp(-((x*x*x * 0.044715 + x) * 1.5957692)))
```

This is the tanh-approximation GELU form expressed through a sigmoid identity. It is separate from the two-plane gated activation in `FUN_18012d460`; those kernels must not be conflated.

The x86 vector implementations use custom exponential/reciprocal approximations and different vector grouping. The initial Android port deliberately targets the scalar function `FUN_18012ca50` rather than copying x86 instructions. Bitwise equivalence with AVX/SSE is not claimed; the scalar port retains the source formula and float32 evaluation order.

## Residual merge

The scalar routine `FUN_1800d8720` confirms the per-element expression:

```text
dst[i] = (dst[i] + bias) * scale + residual[i]
```

VEA implements this as a separate operation so that the calling layer can preserve the exact stage order. It permits exact aliasing between destination and residual buffers; partial overlap is unsupported.

## Android implementation

The following portable scalar operations are implemented in `libveas5tensor.so`:

- `vea_s5_reduce_sum_sumsq_f32`
- `vea_s5_apply_gelu_f32`
- `vea_s5_residual_affine_add_f32`
- `vea_s5_depthwise_conv7x7_reflect_f32`

JNI/Kotlin wrapper methods are exposed on `NativeS5TensorBridge`:

- `reduceSumAndSquares`
- `applyGelu`
- `residualAffineAdd`
- `depthwiseConv7x7Reflect`

Native tests cover reference formula comparison for GELU, affine and residual ordering, depthwise border behavior, and invalid input handling. The latest Android CI run must pass before a package generated from the new changes is considered verified.

## Boundaries still missing

The current port has individual scalar primitives and a partial sequence analysis, not the full layer or model inference runtime. The following are still required:

- the complete tensor operation wrapper called by `FUN_1800c3740` / `FUN_18013aa00`;
- full feature/conditioning tensor construction and shape propagation;
- complete recurrent forward execution (the parameter naming/packing path alone is insufficient);
- the remainder of convolution and decoder operators;
- spectral/audio rendering integration and tested output-buffer semantics;
- an end-to-end model load and differential audio test against the authorized VOCALOID7 reference.

No Megpoid V7 voice audio has yet been generated by VEA on Android.
