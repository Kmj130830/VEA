# S5API 7x7 depthwise convolution — ARM64 scalar port

Date: 2026-11-19

## Evidence and call path

The 7x7 path is selected in `FUN_1800c67e0` only when both recovered kernel dimensions are 7:

- `local_154 == 7`
- `local_13c == 7`

That function obtains the selected kernel address from `FUN_18012e0d0` (`MRW_DWCONV_SIMD`) and invokes it through an indirect function pointer. The dispatcher selects:

- `FUN_18012f280` when `MRW_DWCONV_SIMD` begins with `'0'` (scalar fallback);
- `FUN_180130110` when the x86 feature check enables its AVX2 path;
- `FUN_18012e220` for the remaining supported vector path.

The Windows SIMD implementations cannot be used on Android ARM64. The scalar routine at `FUN_18012f280` is the portable reference target.

## Recovered scalar contract

The scalar routine has ten parameters, recovered from its function body and Windows x64 entry sequence:

1. output float pointer;
2. input row 0 float pointer;
3. input row 1 float pointer;
4. input row 2 float pointer;
5. input row 3 float pointer;
6. input row 4 float pointer;
7. input row 5 float pointer;
8. input row 6 float pointer;
9. pointer to 49 float weights;
10. signed integer row width.

The first four pointer parameters arrive in RCX/RDX/R8/R9. The remaining six arguments are read from the caller's stack parameter area at the callee prologue. The routine reads weight entries through index `0x30` (48), confirming 49 weights.

Output has `width` elements. For each output coordinate `x`, it accumulates a row-major 7x7 stencil:

```text
output[x] = sum(row=0..6, col=0..6)
    input_rows[row][reflect(x + col - 3, width)]
    * weights[row * 7 + col]
```

Horizontal border handling is reflect-without-edge-repeat:

- negative index `i` maps to `-i` (`-1 -> 1`, `-3 -> 3`);
- index `i >= width` maps to `2 * width - i - 2` (`width -> width - 2`).

The source divides the work into first-three, interior and last-three output regions. The scalar port preserves the same index mapping with a single general loop. The recovered caller passes seven source-row pointers when it chooses this 7x7 path. Widths below 7 are rejected by the port because the single-reflection mapping would no longer be sufficient for the supported kernel window.

## Android implementation

The new function is:

`vea_s5_depthwise_conv7x7_reflect_f32`

Files:

- `app/src/main/cpp/vea_s5_dwconv.cpp`
- `app/src/main/cpp/include/vea_s5_tensor.h`
- `app/src/main/cpp/tests/vea_s5_tensor_test.cpp`

It is linked into `libveas5tensor.so` and therefore built for `arm64-v8a` by the Android NDK workflow. The current implementation is a portable scalar kernel, not yet a NEON-optimized kernel. Its output buffer must not overlap input rows or the weights.

## Tests

The native test verifies:

- exact 7x7 all-ones convolution output for all seven positions of a seven-sample input row;
- the first-weight impulse response at every horizontal coordinate, explicitly exercising both reflected borders;
- rejection of a too-narrow width and null input row list.

The Android CI native-test step passed after this kernel was added. The complete APK build and ARM64 shared-library extraction also passed for the same commit.

## Boundary of this milestone

This kernel is one verified internal DSP primitive, not a complete network layer or singing renderer. The surrounding model execution graph, recurrent block, other convolution shapes, feature generation, spectral decoder and audio synthesis remain unimplemented. No Megpoid V7 audio has been generated by this Android port.
